# BIZNES OS — Telegram-бот (верификация, оплата, напоминания)

Этот бот — отдельная программа на Node.js. Она должна **постоянно работать на сервере**
(VPS, Railway, Render, обычный компьютер, который не выключается, и т.п.) — Telegram-бот
не может жить внутри статичного `BIZNES_OS.html`, у которого нет своего сервера.

## Что делает бот
- Верификация номера при регистрации (кнопка «Подтвердить» в чате).
- При нажатии «Купить» в приложении открывает чат и присылает реквизиты для оплаты.
- Принимает фото чека и пересылает администратору с кнопками «Подтвердить» / «Отклонить».
- После подтверждения администратором сам открывает доступ (пишет в Firebase) и
  присылает пользователю сообщение об успешной оплате.
- Раз в день (09:00) шлёт напоминание за 1 день до окончания подписки и помечает
  просроченные подписки как `expired`.

## Установка

1. **Создайте бота** у [@BotFather](https://t.me/BotFather) → `/newbot` → получите токен
   вида `123456:ABC-DEF...`. Придумайте username бота (например `BiznesOS_bot`) — впишите
   его без `@` в `BIZNES_OS.html`, в строку:
   ```js
   var TELEGRAM_BOT_USERNAME = 'BiznesOS_bot'; // ← замените на свой
   ```

2. **Скачайте ключ сервисного аккаунта Firebase**: Firebase Console → ⚙️ Project settings
   → Service accounts → «Generate new private key». Сохраните файл как
   `serviceAccountKey.json` рядом с `telegram-bot.js` (он уже в `.gitignore`-стиле — не
   выкладывайте его публично, это полный доступ к базе).

3. **Включите Realtime Database** в Firebase Console, если ещё не включена
   (Build → Realtime Database → Create database), регион любой.

4. **Установите зависимости и запустите:**
   ```bash
   cd telegram-bot
   npm install
   BOT_TOKEN=123456:ABC-DEF... node telegram-bot.js
   ```

5. **Узнайте свой chat_id администратора**: напишите боту `/myid`, скопируйте число и
   перезапустите бота с переменной:
   ```bash
   BOT_TOKEN=... ADMIN_TELEGRAM_CHAT_ID=123456789 node telegram-bot.js
   ```
   Без этого бот не сможет присылать вам чеки на проверку.

6. **Впишите реальные платёжные реквизиты** в `telegram-bot.js`, в константу
   `PAYMENT_REQUISITES` (сейчас там заглушка).

7. Чтобы бот не останавливался при закрытии терминала, запускайте его через
   [pm2](https://pm2.keymetrics.io/) (`pm2 start telegram-bot.js --name biznes-bot`),
   `systemd`-сервис или на хостинге типа Railway/Render (Background Worker).

## Firebase Realtime Database — правила

В Firebase Console → Realtime Database → Rules вставьте содержимое `database.rules.json`
из этой папки (базовый вариант, ниже — важные оговорки по безопасности).

## ⚠️ Важно про безопасность (прочитайте перед запуском в бою)

Текущая схема — рабочий MVP, но не production-grade защита:

- **Вход в приложении сделан без Firebase Authentication** (номер+пароль сверяются
  прямо в браузере). Конфиг Firebase (`apiKey`, `databaseURL` и т.д.) в публичном
  HTML-файле — это нормально для Firebase *только если правила базы данных жёстко
  ограничивают доступ*. Сейчас правила специально оставлены открытыми (`.read/.write: true`
  на `users`), иначе не будет работать админ-панель в браузере (она тоже пишет
  напрямую в базу, а не через бота).
- **Из-за этого** технически подкованный человек может напрямую обратиться к
  Firebase REST API и, например, самостоятельно записать себе «активную подписку»,
  минуя оплату, или прочитать список всех номеров телефонов и хеши паролей.
- **Пароль admin (`+992978117811` / `050905`) захардкожен в клиентском JS** — это
  тоже видно любому, кто откроет исходный код страницы.

**Как закрыть эти дыры (следующий шаг, не сделано в этой версии):**
1. Перевести админ-панель на серверные вызовы (например, через отдельные защищённые
   HTTP-эндпоинты этого бота или Cloud Functions), которые используют
   `firebase-admin` (у него есть полный доступ и правила базы данных его не
   ограничивают) — тогда правила базы можно закрыть от публичного доступа полностью.
2. Заменить самодельный вход на настоящий Firebase Authentication (например,
   Custom Token, который выдаёт бэкенд после проверки пароля) — тогда правила можно
   писать по `auth.uid`, а не оставлять `true`.

Если нужно — можем сделать это отдельным шагом.
